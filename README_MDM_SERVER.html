Servidor MDM HL7 - Documentación Técnica

¿Qué es?

El Servidor MDM HL7 es una aplicación Python que recibe mensajes HL7 MDM^T02 vía MLLP, extrae información clínica y documentos PDF embebidos (en base64), almacena los datos en una base Oracle y realiza extracción automática de texto desde los PDFs para su consulta y trazabilidad.

Flujo de funcionamiento

  1. Escucha conexiones TCP en el puerto 2590 (configurable).
  2. Recibe mensajes HL7 MDM^T02 enmarcados con MLLP (VT, FS, CR).
  3. Extrae campos clínicos y el PDF (base64) desde el segmento OBX-5.
  4. Decodifica y guarda el PDF en disco y en la base de datos (campo PDF).
  5. Extrae el texto del PDF (usando PyMuPDF y OCR si es necesario).
  6. Guarda el texto extraído en el campo INFORME_TXT de la base de datos.
  7. Guarda el mensaje HL7 original y responde con un ACK HL7.

Principales componentes

  • MLLP Server: Socket TCP multihilo que recibe mensajes HL7.
  • Parsers HL7: Funciones para extraer campos y PDF desde los segmentos HL7.
  • Gestión de PDF: Decodificación base64, guardado en disco y base, extracción de texto (PyMuPDF, OCR).
  • Base de datos Oracle: Inserción de todos los campos relevantes, PDF y texto extraído.
  • Respuestas HL7: Generación y envío de ACK tras procesar cada mensaje.

Requisitos

  • Python 3.8+
  • Paquetes: cx_Oracle, pymupdf, opencv-python, numpy, pillow, pytesseract
  • Oracle Client instalado y accesible
  • Acceso a la base de datos Oracle con la tabla SEGMENTOS_HL7.MENSAJES_MDM

Ejemplo de flujo

  1. Un sistema externo envía un mensaje HL7 MDM^T02 con un PDF embebido en base64 en OBX-5.
  2. El servidor recibe el mensaje, lo parsea y extrae el PDF.
  3. El PDF se guarda en disco y en la base de datos.
  4. Se extrae el texto del PDF y se almacena en INFORME_TXT.
  5. Se responde con un ACK HL7 al emisor.

Notas y buenas prácticas

  • El servidor es multihilo y puede recibir múltiples mensajes simultáneamente.
  • El texto extraído del PDF se limpia y se almacena para facilitar búsquedas y auditoría.
  • Todos los errores y eventos relevantes se registran en consola para trazabilidad.
  • El ACK HL7 se genera siempre, incluso si ocurre un error, para evitar bloqueos en el emisor.
